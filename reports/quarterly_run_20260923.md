## 四、四项验证的证据

### 1. 新建跨品牌体检工具 `tools/verify_quarterly_run.py`

把「人工费 50000」事故的三类特征固化成断言，下次跑批能自己喊出来：

- **量级异常**：人工费超币种绝对上限 / 超同类中位数 100× / 既超物料费 20× 又超中位数 10×；
- **静默失联**：某 brand×country 有已发现机型但**本季 0 条价格**（节点选错、接口改版的典型特征）；
- **结构卫生**：孤儿快照、重复快照、非正价格、CNY 折算越界、跨区同价串味。

首次运行抓出 1 条 ERROR，经核查为**误报并已修正判据**（见第五节）。

### 2. 三星解析对照 `tools/probe_parse_divergence.py`（非破坏性）

在**真实接口数据**上同时跑旧解析器与 JSON 解析器：

```

对照原始金额值：18 个；解析分歧：0 个
```

结论：三星中国区的 `PART_PRICE` 一例都没有 3 位小数，旧解析器当时恰好正确；
切成 JSON 解析器后结果完全一致，属于**零风险加固**（防的是「135.000」这类未来值）。

## 五、跑批中发现并处置的问题

| # | 现象 | 定性 | 处置 |
|---|---|---|---|
| 1 | `[warn] 实时汇率获取失败，回退 STATIC_RATES: timed out` | 瞬时故障，**已自愈** | 汇率表实为 `live:open.er-api.com` @ `2026-09-23T15:28:26`，重试成功。无需处理 |
| 2 | `RuntimeError: Event loop is closed`（Traceback） | **无害** | asyncio 子进程对象在解释器退出时被 GC 触发的告警，发生在 `[finish]` 落库之后，不影响数据 |
| 3 | 体检报 `oppo/MXN 人工费 > 20×物料费`（mx OPPO A6c：人工 240 / 物料 4.11） | **误报，已修判据** | 实为 OPPO 墨西哥对「卡托/数据线」类配件收固定最低人工费 240 MXN，而卡托物料本身仅 4.11 MXN；同机型部件类是 650 MXN，结构自洽，属真实定价。判据已改为「比值越界**且**量级离群（>10×同类中位数）」双重条件——该误报不会漏掉真实事故（50000 vs 中位数 50） |
| 4 | `samsung/de` 出现 `官方重名条目去重：367 → 366` | 正常 | 官方同一机型两个条目（含不间断空格 `\xa0`）归一后重名，按「价表更全/命名更规范」保留其一 |

## 六、遗留与建议

1. **`run_logs.status` 语义重叠（P2）**：`[resume]`（本季已抓）与 `[skip] unavailable`
   （官网不提供）都记为 `skipped`，事后无法区分「正常续跑」与「该区域根本没数据」。
   建议拆成 `resumed` / `unavailable` 两种状态，便于覆盖度审计。
2. **数据新鲜度**：Apple / Samsung / Vivo / Xiaomi 的库存为 09-17 ~ 09-18。
   季度内不重抓是既定设计；若需要把某品牌刷到最新，用
   `python -m crawler.run --brand <b> --country <c> --force` 强制单区域重抓即可。
3. **本次未覆盖**：`config.push.json` 不存在，推送阶段仅本地预览（`enabled=false`），
   实际未对外发送——符合预期，但意味着**异动推送链路本次未被真实验证**。
